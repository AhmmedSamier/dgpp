# KDA M2 validation record — 2026-08-27

Purpose: record the M2 (KDA operators and state manager) correctness and
profiling evidence: kernel parity, chunked-prefill equivalence, state
geometry, snapshot round-trip, graph-capture determinism, reference-dump
parity, and batch-1 state-traffic measurement.

## Environment

- DGX Spark GB10, AArch64, Linux `6.17.0-1026-nvidia`;
- NVIDIA driver `580.173.02`; CUDA 13.0; SM 12.1, 48 SMs;
- M2 working tree (post layout-freeze; see `git status` at commit time);
- no model server resident; GPU idle between runs;
- builds: `release`, `ci` (warnings-as-errors), `ubsan`, `asan` presets.

## Correctness (CTest, release and ci builds)

`ctest` result: 7/7 passed (`unit`, `checkpoint_audit_test`, `kda_test`,
`kda_dump_generate`, `kda_dump_test`, `doll_selftest`,
`flag_protocol_test`).

The KDA suite (`kda_test`) pins:

- **Geometry**: TP=4 `[16,128,128]` FP32 recurrent state (1,048,576 B/layer),
  `[6144,6]` BF16 conv slot (73,728 B/layer; committed width 3 = 36,864 B),
  38,158,336 B fixed slot per request (36.39 MiB incl. draft reserve) — the
  DESIGN §7.1 numbers exactly.
- **Conv kernel**: bf16 outputs within 1 ulp of the host reference across
  T ∈ {1,2,3,64,2048}; rolled history bit-exact; speculative reserve columns
  provably untouched; short-chunk (T < width-1) state blending pinned.
- **Recurrent kernel**: state within 1e-4 relative (1e-5 absolute floor) and
  outputs within 1 bf16 ulp of the fp32 host mirror AND the fp64 oracle at
  T ∈ {1,7,257} plus real per-rank geometry (16 heads × 128) at T=65;
  includes an all-zero token (l2norm eps path, no NaNs).
- **Chunked vs unchunked**: conv+recurrence path is bitwise identical for
  512 tokens split 256+128+127+1 (decode-style tail) vs one call — fp32
  state and bf16 conv history round-trip through memory exactly.
- **Full layer vs host reference**: small geometry (hidden 64, 2 heads)
  incl. fp64 oracle, and real geometry (hidden 4096, 64 heads,
  in_proj_cols 24896, 24576 conv channels, dt_bias 8192) at T=4; declared
  tolerances: outputs ≤2 bf16 ulps with ≤2% outlier elements and L2 ≤5e-3;
  state drift ≤0.5% of state scale, L2 ≤1e-3.
- **Chunked full layer** (2048 = 1024+1024 and 2047+1): the 1024+1024 split
  produced bit-identical state and outputs (cuBLASLt picked identical
  algorithms); the 2047+1 split drifted 0.13% of state scale (L2 1.8e-4) —
  bf16 GEMM outputs differ by ~1 ulp across m, which the recurrence then
  carries; the recurrence itself is exact (bitwise test above).
- **Graph capture**: decode-step (T=1) capture/replay vs eager is bitwise
  identical on outputs and state for two different inputs (GEMM plans
  prebuilt outside capture; no allocation during capture).
- **Snapshot round-trip**: export → import into a second slot → continued
  execution reproduces outputs bitwise; tampered headers (tp, layers,
  dtypes, payload size, reserved field) are rejected before any bytes land.
- **Head-slice TP readiness**: a 16-head rank slice reproduces the full
  64-head run's core outputs for its heads within 2 bf16 ulps (L2 ≤1e-2).
  This test caught a real sharding subtlety: the merged conv weight is
  `[q(all heads)|k|v]`, so a rank's slice is per-section, not a prefix.
- **Reference-dump parity (pure backend)**: device layer vs the
  stdlib-python oracle is bit-identical on layer_out/core_out/conv state;
  FP32 state within 5.6e-8 L2. Developing this caught two oracle-side bugs
  (a Python slice-copy that dropped the rank-1 state update, and the fused
  layout reorder), which is the point of triangulating three independent
  implementations.

Sanitizers: `ubsan` ctest 7/7 passed in 9.6 s; `asan` ctest 7/7 passed in
10.5 s (`detect_leaks=0`). Two setup fixes made those times possible and
are worth remembering: the sanitizer presets originally inherited the
`Debug` build type (`-O0`), which made instrumented host-reference code
~20× slower than it needs to be — both presets now build
`RelWithDebInfo` — and test weights are generated as bf16 bit patterns
straight from the hash (sign/exponent/mantissa fields), not through
Box-Muller plus a rounding encoder; parity tests need distinct values at
sane scales, and the host reference consumes the identical bits either way.

## Batch-1 state-traffic profile (M2 exit criterion)

Command: `kda_bench --iters 50 --warmup 5` (idle node; concurrent
`nvidia-smi` sampling showed ~2,398–2,405 MHz SM clocks and 12–25 W during
timed work; no concurrent model server). A repeat run (`--iters 30`) agreed
within run-to-run variance (85.0/63.4 GB/s vs 86.4/63.5 GB/s).

| case | mean | min–max | state bytes/step | effective |
|---|---:|---|---:|---:|
| recurrent kernel only, TP=1 (64 heads, 34 layers) | 3.301 ms | 3.228–3.643 | 272.0 MiB | 86.4 GB/s |
| recurrent kernel only, TP=4 rank (16 heads) | 1.123 ms | 1.103–1.221 | 68.0 MiB | 63.5 GB/s |
| full KDA layer decode (T=1), TP=1 | 1.324 ms | 1.302–1.545 | — | — |
| full KDA layer prefill chunk (T=2048), TP=1 | 23.787 ms | 23.570–24.090 | — | — |

Interpretation (recorded so nobody has to re-derive it):

- The recurrent decode kernel is **latency-bound, not bandwidth-bound**: at
  T=1 it launches ceil(V/32)×heads blocks (256 at TP=1, 64 at TP=4) of 128
  threads — far below GB10's 48-SM occupancy, and 34 sequential per-layer
  launches add per-launch overhead at 2–8 MiB per launch. The 230 GB/s
  planning floor does not bind here.
- Identified optimization path (not M2 scope): batch all 34 layers into one
  launch (uniform layer stride in the state pool makes this a grid.z
  extension), and/or split v-rows more finely. Register pressure (167 regs
  at K=128, zero spills) already supports the current layout.
- The full-layer decode at TP=1 spends ~0.9 ms streaming the 204 MB fused
  projection per layer — weight-bandwidth-dominated, as the decode traffic
  model intends (DESIGN §3); the recurrent state adds ~0.1 ms.
- Prefill at 2048 tokens/chunk/layer (23.8 ms, TP=1, sequential recurrence)
  extrapolates to ~0.81 s per 2048-token chunk across 34 layers. The
  chunked-parallel (WY-representation) prefill kernel of the reference is
  the known optimization for M9; M2 deliberately ships the shared
  prefill/decode recurrence for exactness.
