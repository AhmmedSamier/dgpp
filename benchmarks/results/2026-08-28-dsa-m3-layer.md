# DSA M3 Layer Benchmarks — 2026-08-28

## Environment

- NVIDIA GB10 (DGX Spark), max SM clock 3003 MHz, driver 580.173.02, CUDA 13.0
- Release build (`-O3`), idle node, `dsa_bench` defaults unless noted
- Planning floor: 230 GB/s effective (docs/measurements.md M1 memory probe)

## Full DSA layer, real GLM-5.3-Flash geometry, TP=1, context 65,536

| case | mean | min | max | effective |
|---|---|---|---|---|
| decode eager (T=1) | 2.235 ms | 2.201 | 2.415 | 113.7 GB/s |
| decode graph replay (T=1) | 2.198 ms | 2.168 | 2.238 | 115.6 GB/s |
| prefill chunk (T=2048) | 317.9 ms | 317.4 | 318.6 | 6,443 tok/s |
| prefill chunk (T=8192) | 1981.4 ms | 1980.8 | 1981.8 | 4,134 tok/s |

Decode traffic per step: 238 MiB weights + 2 MiB index stream + 2 MiB
gathered latents. Extrapolated to all 11 DSA layers: ~24.2 ms/token
(single-rank; TP=4 shares the weight stream).

## Optimization log (decode, same bench, this session)

| change | decode ms | effective |
|---|---|---|
| layer phase, pre-optimization | 13.26 | 19.2 GB/s |
| native e4m3/bf16 hardware conversions (was branchy software decode) | 6.00 | 42.4 |
| split-32 bitonic keys + thread-strided merge loads + 256-thread select blocks | 4.67* |
| split-KV n_split 4→32 (128 blocks vs 16), empty-split early exit | 3.55 | 71.6 |
| attn smem stride padding (32-way bank conflicts → ≤2-way) + float4 c RMW | 2.24 | 113.7 |

*at kSelectGridBlocks=16 (grid sweep: 12/16/24/32 → 2.28/2.22/2.22/2.26 ms).

Measured bottlenecks before each fix (clock64 phase timers, since removed):
the select merge's single-block bitonic was 97% of the select kernel; the
warp-strided merge key loads serialized 512 dependent global loads per warp
(57%); attention's unpadded [head][512]/[group][64] smem layout bank-
conflicted every access 32 ways (85% of attention cycles).

## Interpretation

- The projection GEMMs (cuBLASLt, m=1) now dominate decode at ~1.0 ms —
  238 MiB of weights at ~240 GB/s, i.e. AT the planning floor. Custom
  kernels account for the remaining ~1.2 ms (select 0.55, attention 0.2,
  absorb+vout 0.2, norms/updates 0.1); the select merge's single-block
  bitonic (0.2 ms) is the largest remaining custom-kernel cost and the next
  optimization target if decode must approach the roofline.
- Graph replay matches eager within noise (no launch-bound behavior).
- Prefill throughput drops at 8,192-token chunks: the dot-tile budget
  (64 MiB) shrinks query tiles to ~30 rows at that context, multiplying
  K-cache gather+GEMM passes. A larger dot budget or persistent per-request
  gather buffer would recover it if prefill is the binding constraint.
- Run-to-run repeat (5-iter vs 30-iter runs) agrees within 1.5%.
